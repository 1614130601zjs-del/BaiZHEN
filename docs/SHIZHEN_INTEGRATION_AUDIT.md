## 一、已核验的拾帧功能面

拾帧主入口 `index.js`（约 660 KB 文本）包含以下子系统：

1. **取景与提示词组装**：手动提示词、中文转 Tag、结构化角色栏位、角色名解析、角色提示词拆分、最终 NAI 提示词预览。
2. **画师串与组合**：画师串库、预设组合、单独选择画师串/Vibe、角色卡绑定组合、配置迁移。
3. **Vibe 管理**：Vibe 池、分组引用、导入/导出、图片编码、编码模型、Information Extracted、参考强度、重复项合并。
4. **词笺/角色词库**：角色词条、别名、角色卡绑定、用户外貌、缺失角色名提醒。
5. **同人作品库**：角色名别名 → 标准 Danbooru `英文名(作品名)` 规范 tag 的兜底映射；角色词条优先于作品库。
6. **通用词库**：女性/男性/通用词组，支持全局默认与角色卡范围、启停、插入位置及分组选择。
7. **小剧场**：剧情词/画面词生成、主 API 静默生成或自定义 API、读取角色卡/预设/当前激活世界书/聊天历史、彩蛋聊天室输出、图片重 Roll、收藏与分组管理。
8. **小剧场收藏快照**：按具体图片标记定位标题和聊天室片段，收藏时保存快照，后续正文变化不应改变旧收藏；小剧场隐藏状态与角色相册收藏状态独立。
9. **角色相册与提示词图集**：角色相册、提示词图集、图片详情、排序/布局、收藏移动、批量操作。
10. **底片/影像缓存**：图片记录、消息锚点关联、批量下载/删除、缓存清理、状态栏图片记录与修复。
11. **拾帧工坊**：以图片为底图，支持画笔/橡皮/矩形蒙版、撤销/重做、图生图/局部重绘、Strength/Noise/Seed、可选带入当前 Vibe、结果回存缓存或相册。
12. **影像美化**：聊天标题徽章、相册卡片、彩蛋聊天室联动样式；自带风格与自定义 CSS，支持导入/导出/删除/AI 协作骨架。
13. **聊天正文触发**：`image###…###` 标记原位替换为按钮；另有状态栏图片标记扫描、去重、重试与修复。
14. **悬浮球/果冻动效**：可配置悬浮球图标；图片可有点击/拖动反馈、局部选区、连续摇晃等动效。
15. **迁移工具**：扫描智绘姬设置并预览迁移内容。
16. **Android 本地素材库**：独立 Android 工程；README 记录了 ZIP 快照导入、SHA-256 校验、SQLite 快照历史、回环 HTTP 服务与 Bearer 配对。README 同时明确尚未完成真机、Termux、酒馆端到端联调，不能视为已验证可用。

独立模块：
- `worldbook-manager.js`：世界书模式管理、按角色卡 profile、核心书/世界观特化书、条目覆盖、接管前状态记录与恢复。
- `trigger-core.js`：`image###` 解析、最终消息检查、稳定 trigger id、任务状态去重/重试。
- `vault-adapter.js`：仅对 `extension_settings.shizhen` 做快照适配；图片资源按 SHA-256 引用化。
- `float-ball.js`：拾帧悬浮球及摇晃反馈。

## 二、柏宝绘已具备、应保留而非重复移植的能力

已从 `codex/stream-rebuild` 源码确认：
- **多后端生图**：NovelAI、ComfyUI；柏宝绘共用 `generate.ts` 生成路径。
- **自动分析与流式出图**：独立 LLM 分析、标记注入、流式批次、任务接管/重定位、重试、诊断。
- **原生漫画引擎**：结构化协议、分镜规划/布局、人物和衣着连续性、漫画规则及测试。
- **角色固定外貌档案**：本聊天/全局两层、字段化外貌、AI 变更历史与回滚、全局锁定、视觉状态档案。
- **图库与楼层生图卡片**：按角色目录浏览、灯箱、提示词侧写、多选删除、批量导出原图、缺失图片降级。
- **画师串管理**：内置只读画师串、用户自定义、搜索、预览图、复制、批量删除、正负面/质量词配置。
- **Vibe**：独立数据存储、编码、分组、强度、`.naiv4vibe` 支持及智绘姬只读导入。
- **悬浮球和主题**：书签/圆形/方形、边缘吸附、拖动、自定义图标；内置日间/夜间/粉彩/木白/跟随 ST 主题。
- **请求历史、公开 API、ComfyUI 工作流、NAI 限流与重试**。

## 三、差异矩阵（第一轮）

| 拾帧能力 | 柏宝绘对应能力 | 初步结论 | 融合方向 |

| 世界书模式管理器（核心书+世界观书、profile、条目绑定、接管/恢复） | `autoTag/context.ts` 会读取当前激活世界书并渲染条目；未见同等的挂载管理器 | **部分具备** | 新增独立世界书生图模式；世界书状态由单一管理器接管并可完整恢复 |
| 小剧场/剧情聊天室 | 已新增独立小剧场页，复用主 API 与柏宝绘生图后端 | **第一版已落地** | 继续补齐收藏分组、头像库、聊天室编辑与更完整的剧情生成配置 |
| 小剧场图片标题与聊天室快照 | 楼层图片元数据、图库侧写 | **部分具备** | 新增按任务/图片槽位保存的不可变快照，不依赖未来消息内容 |
| 角色词条/别名/角色卡绑定 | 字段化角色外貌库，含 fandom 字段 | **部分具备** | 评估统一数据模型，补别名解析与取景角色绑定，不另建冲突的外貌真源 |
| 同人作品库 canonical tag 兜底 | fandom 字段与角色提示词锚定 | **未见等价映射库** | 作为角色 tag 解析的低优先级 fallback，角色档案优先 |
| 通用词库（性别分组、全局/角色卡作用域） | 自动提示词/质量词配置 | **未见等价词组管理** | 新增可选的通用词注入层，明确插入位置并避免漫画提示词重复注入 |
| 画师串角色卡组合绑定 | 画师串库、内置库、预览图、批量管理 | **部分具备** | 保留柏宝绘画师串管理器，补独立的角色卡组合绑定，不复制画师串存储 |
| Vibe 池/组/编码/导入导出 | Vibe 存储、分组、编码、导入导出、智绘姬导入 | **高度重叠** | 逐项对照编码格式、去重、池/组关系、强度语义；只补缺口 |
| 提示词库与提示词图集 | 自动 Tag 提示词配置、图片图库 | **部分具备** | 评估提示词模板库和“提示词→收藏图片”关联，不复制普通图库 |
| 拾帧工坊（蒙版/局部重绘） | 楼层提示词编辑、ComfyUI/NAI 出图 | **未见等价蒙版工坊** | 可作为独立图像编辑入口，优先复用柏宝绘后端能力；确认 NAI inpaint 能力边界 |
| 聊天影像 CSS（标题/卡片/聊天室联动） | 插件自身主题与楼层卡片样式 | **部分具备** | 新增作用域隔离的聊天影像样式层，不影响柏宝绘 UI 和 ST 全局样式 |
| image### 手动触发/状态栏图片标记 | 自动 Tag、流式任务队列、楼层卡片 | **触发方式不同** | 保留柏宝绘任务/卡片/队列；为拾帧标记增加适配器，不复制第二套生成队列 |
| 悬浮球 | 已有悬浮球 | **已具备主体** | 只评估果冻/摇晃等反馈，不替换柏宝绘拖动、吸附与图标实现 |
| Android 本地素材库/快照 | 无对应 Android App | **独有但未实机验证** | 后置阶段；先审协议、威胁面、恢复兼容性，再决定是否纳入主版本 |
| 漫画分镜引擎 | 柏宝绘原生漫画引擎及测试 | **柏宝绘更完整** | 明确保留柏宝绘实现，不移植拾帧漫画引擎 |

## 四、已确认的架构约束

1. 保留柏宝绘原生生图模式。
2. 新增拾帧世界书生图模式，用户自主选择；两种模式独立配置、独立上下文逻辑。
3. 模式切换不得丢失另一模式设置；同一生图任务只能由一个模式接管。
4. 世界书模式退出或切换时，恢复接管前的全局挂载和条目状态。
5. 两种模式共用柏宝绘生图后端与生成/存储基础设施，不建立第二套后端。
6. 漫画引擎保留柏宝绘原生实现；拾帧小剧场作为独立创作功能评估，不把拾帧漫画引擎并入柏宝绘漫画链路。
7. 新增模块通过清晰的适配层接入，预留第三种模式扩展点。

## 六、风险提示

- 世界书挂载状态是酒馆全局共享状态，必须保证只有一个模块负责写入；异常路径也要恢复。
- 小剧场必须对每张图片建立稳定任务 ID，避免同一消息多张图的快照串位。
- 角色外貌库与角色词条库存在数据交集，不能形成两个互相覆盖的真源。
- 任何自动提示词注入都要与柏宝绘漫画/普通模式分开验证，防止通用词、质量词重复叠加。
- Android 端目前 README 明确标注未完成真机联调，不能把协议存在当作产品验收通过。

### 世界书模式接口核验与第一轮风险修复

- 已对照 SillyTavern `release` 分支 `public/scripts/world-info.js`：确认 `selected_world_info`、`world_info`、`world_names` 是模块导出；`saveWorldInfo(name, data, immediately)` 与 `checkWorldInfo(chat, maxContext, isDryRun, globalScanData)` 也有导出。当前模式适配器调用的核心名称与该版本源码一致。
- `checkWorldInfo` 的激活条目包含 `world` 来源书名；柏宝绘 `fetchWorldInfo` 使用该字段限制允许进入上下文的书名。宿主旧接口丢失来源字段时，世界书模式保持严格空结果，不回退混入其他书。
- `WORLDINFO_SETTINGS_UPDATED` 是酒馆公开事件类型；扩展可通过 `eventSource.emit` 触发设置更新通知。
- 导航栏 `NavBar.vue` 直接遍历 `PAGES` 注册表，因此“生图模式”入口会正常显示。
- 修复了“选择模式即提前启用”的问题：现在只有点击应用并成功后，持久化 `profile.enabled` 才保持为 `true`；仅选择模式不会提前改变生图上下文。
- 修复了应用流程的恢复点时序：在改动全局挂载或条目状态前，先持久化原始全局挂载和两本目标书的 `disable` 快照；切换目标书时保留整个接管期间的 managed book 集合，避免旧目标书残留挂载；应用失败时立即尝试恢复。

接口核验来源：
- https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/world-info.js
- https://docs.sillytavern.app/for-contributors/writing-extensions/

注意：该核验针对当前公开 `release` 源码；用户实际酒馆版本仍需运行时验证。失败回滚、重启恢复、用户手动修改挂载、角色/群聊切换仍须在真实酒馆环境验收。

## 八、第二阶段代码落地（2026-11-24，持续开发中）

本阶段在上述世界书模式基础上继续补齐拾帧画师串/Vibe 组合、数据迁移和状态栏标记入口：

- `src/backends/shizhenArtistProfiles.ts`：使用柏宝绘稳定 ID 表达拾帧数组下标组合；正文、状态栏、彩蛋分别支持角色绑定与通用回退；请求级副本应用组合，不改动原生全局画师串/Vibe 开关。Vibe 组合支持单条和分组两种选择。
- `src/pages/backend/panels/NaiArtistProfiles.vue`：新增拾帧式组合与角色卡绑定 UI；三种目标分别配置组合与尺寸。
- `src/backends/shizhenVibeImport.ts`：扩展拾帧 Vibe JSON/ZIP 包装结构识别，并保留 V3 的编码载荷语义。
- `src/backends/shizhenBackupImport.ts`：按拾帧真实完整备份字段解析 `presets`、`combinations`、`bindings`、Vibe 分组 `refs` 与 `vibePool`，将组合下标映射为柏宝绘稳定 ID。
- `src/pages/backend/panels/NaiShizhenMigration.vue`：新增完整备份导入预览、画师串/Vibe 去重、角色绑定冲突跳过、失败时清理新写入的 Vibe 文件，以及只导出兼容数据的备份功能。导出不包含 API Key、聊天记录或影像缓存。
- `src/floor/statusBar.ts`：新增对拾帧 `.scanning` / `data-qlPrompt` 状态栏标记的扫描入口；复用柏宝绘统一生成接口和 NAI 限流队列，独立应用状态栏组合；保存历史图并支持切换、重 Roll、删除和失败重试。任务缓存按聊天、消息、swipe、序号和提示词区分。
- `src/floor/storage.ts`：导出已有结果转上传所需的 Base64 转换方法，状态栏入口复用现有酒馆图片存储能力。
- `src/index.ts`：在设置回灌后启动状态栏观察器，并在总开关变化时刷新。

### 本阶段新增的防护与已知边界

- 角色绑定优先按头像文件名稳定键匹配；只有旧备份留下的 name/index 键才允许名称回退，避免同名角色串绑。
- 导入时先准备待写入对象，提交设置前保留原数组引用；异常时恢复设置引用并清理本次创建的数据文件。
- 状态栏 MutationObserver 监听标记属性变化；生成任务返回时再次校验当前 frame 仍对应原任务，避免旧任务覆盖新标记。
- 状态栏图片缓存加入实际聊天 swipe id，避免相同消息不同 swipe 之间串图。
- 正文的 `[彩蛋]` / `【彩蛋】` 前缀已在楼层生图入口识别并剥离，自动选择 `egg` 配置；状态栏入口仍优先使用 `statusBar` 配置。
